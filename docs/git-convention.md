# Git 컨벤션

기존 커밋 히스토리에서 관찰된 규칙을 정리한 문서입니다. 새 커밋도 이 형식을 따릅니다.

## 커밋 메시지 형식

```
<Type> : <설명>
```

- `Type`은 영문 단어, 첫 글자만 대문자로 표기합니다 (예: `Settings`, `Docs`).
- `Type`과 설명 사이는 공백-콜론-공백(` : `)으로 구분합니다.
- 설명은 한글로 작성하고, `~함`, `~했습니다` 같은 문장형이 아니라 짧은 명사구 제목으로 씁니다.

### 실제 커밋 예시

```
Settings : 프로젝트 시작
Docs : 예시 html 추가
```

## Type 목록

지금까지 실제로 쓰인 Type:

| Type | 용도 |
| --- | --- |
| `Settings` | 프로젝트/빌드 초기 설정 |
| `Docs` | 문서, 예시 자료 추가·수정 |

커밋이 늘어나면 아래와 같은 Type이 추가로 필요할 수 있습니다. 아직 실사용 예시는 없으므로, 위와 같은 `Type : 설명` 형식을 유지하면서 필요할 때 이 표에 추가해 나가면 됩니다.

| Type | 용도 |
| --- | --- |
| `Feat` | 기능 추가 |
| `Fix` | 버그 수정 |
| `Refactor` | 동작 변경 없는 코드 개선 |
| `Test` | 테스트 추가·수정 |
| `Chore` | 빌드 설정, 의존성 등 기타 작업 |

## 브랜치

현재는 `main` 브랜치 하나로만 운영되고 있고, 별도로 정해진 브랜치 전략은 없습니다. 브랜치를 나누기 시작하면 이 섹션에 규칙을 추가하세요.
