# 기능 명세

`sample-html/preview.html` 클릭형 와이어프레임을 근거로 정리한 기능 명세입니다. 아직 백엔드 구현은 없으며, 이 문서는 이후 구현의 기준이 됩니다.

## 사용자 역할

| 역할 | 설명 |
| --- | --- |
| 관리자 | 문제/과제를 관리하고 학생 학습 현황을 모니터링하는 교사 |
| 학생 | 과제를 풀고 자신의 학습 이력을 확인하는 사용자 |

## 도메인 용어

| 용어 | 설명 | 예시 값 |
| --- | --- | --- |
| 문법 항목(category) | 문제가 다루는 문법 주제 | 현재완료, 관계대명사, 수동태, 가정법 |
| 문제 유형(type) | 문제 출제 형식. **Phase 1(MVP)은 객관식(`MULTIPLE_CHOICE`)만 지원**하며, 빈칸/오류 찾기는 이후 단계에서 지원 예정인 미래 범위입니다. | 객관식(Phase 1 지원), 빈칸·오류 찾기(향후) |
| 난이도(level) | 문제 난이도 | 기초, 보통, 심화 |
| 문제 상태(status) | 문제의 공개 상태 | 초안, 사용 중, 사용 중지 |
| 과제 상태(status) | 과제 진행 상태. 서버가 `startDate`/`dueDate` 기준으로 자동 계산합니다 — 오늘이 `startDate` 이전이면 `예정`, `startDate` 이상 `dueDate` 이하이면 `진행 중`, `dueDate`를 지나면 `마감`입니다(둘 다 경계값 포함). 별도의 상태 변경 API는 없습니다. `startDate ≤ dueDate`가 항상 성립해야 하며, 생성·수정 시 서버가 검증합니다. | 예정, 진행 중, 마감 |
| 제출 상태(submissionStatus) | 학생 개인의 과제 수행 상태로, 과제 자체의 `status`와는 별개 개념입니다. 문제 풀이 화면에 처음 진입하면 `IN_PROGRESS`로 시작하고, 최종 제출을 마치면 `SUBMITTED`로 바뀐 뒤 되돌릴 수 없습니다(잠김, 재제출 불가). 아직 한 번도 진입하지 않았으면 `NOT_STARTED`입니다(서버에 아직 레코드가 없는 상태). | NOT_STARTED, IN_PROGRESS, SUBMITTED |
| 진행률(progress) | 과제 진행 상황(0~100). **학생 관점**(`GET /api/me/assignments`)에서는 "이 학생이 임시 저장한 답안이 있는 문제 수 ÷ 과제의 전체 문제 수"이며, 정답 여부와는 무관합니다(최종 제출 전까지 채점 결과 자체를 알 수 없으므로). **관리자 관점**(`GET /api/assignments`, 이른바 제출률)에서는 "대상 학생 중 과제를 최종 제출(제출 상태 `SUBMITTED`)한 학생 수 ÷ 전체 대상 학생 수"입니다. 필드명은 같지만 계산 기준이 다르므로 혼동하지 않습니다. | 84 |
| 학습 유형(StudyRecord type) | 학습 이력의 구분. API 쿼리/응답 값은 `ASSIGNMENT`/`PRACTICE`이며, 화면 표시용 한글 라벨은 각각 "과제"/"자유 학습"입니다. 한글 라벨은 API 값으로 사용하지 않습니다. | `ASSIGNMENT`(과제), `PRACTICE`(자유 학습) |
| 학습 기록 스냅샷 | StudyRecord는 채점 시점의 문제 내용(문법 항목, 난이도, 본문, 보기, 정답, 해설)을 함께 저장합니다. 이후 원본 문제가 수정되거나 상태가 바뀌어도 이미 생성된 학습 기록의 내용은 바뀌지 않습니다(불변). `type: ASSIGNMENT`인 기록은 자유 학습과 달리 문제 하나를 풀 때마다가 아니라 **과제 최종 제출 시점에 한 번에 일괄 생성**되며, 제출 대상 과제를 식별할 수 있는 참조도 함께 저장합니다(진행률·이력 집계에 사용, 응답 필드로는 노출하지 않음). **과제에 포함된 모든 문제마다 1건씩 생성**되며, 임시 저장이 없던(미응답) 문제도 예외 없이 `submittedAnswer: null`, `correct: false`로 스냅샷이 남습니다 — 그래야 원본 문제가 나중에 바뀌거나 삭제되어도 제출 시점의 전체 결과를 그대로 재구성할 수 있습니다. 자유 학습분은 제출 시 답이 항상 필수라 `submittedAnswer`가 비어있을 수 없지만, 과제 제출분은 이 미응답 스냅샷 때문에 `submittedAnswer`가 `null`일 수 있다는 점이 둘의 차이입니다. | — |
| 재응시(reattempt) | 자유 학습에서 학생이 같은 문제를 다시 푸는 것. 이전 제출을 덮어쓰지 않고 매 제출마다 새 학습 기록을 별도로 생성합니다. **과제 수행에는 이 개념이 없습니다** — 과제 진행 중 답안을 바꾸는 것은 임시 저장 값을 덮어쓸 뿐 새 기록을 만들지 않으며, 최종 제출 이후에는 어떤 형태의 재제출도 금지됩니다. | — |

## 0. 로그인 (공통)

- 아이디(`loginId`)와 비밀번호로 로그인한다. 회원가입 화면은 없으며, 계정은 관리자가 사전에 발급한다고 가정한다.
- 로그인 성공 시 계정 유형(관리자/학생)에 따라 각자의 대시보드로 진입한다. 와이어프레임의 역할 전환 버튼은 데모용 토글이며, 실제로는 로그인한 계정의 유형으로 고정된다.
- Access token 만료 시 refresh token으로 재발급받는다. 재발급도 만료되면 다시 로그인해야 한다.
- 로그아웃 시 서버에 저장된 refresh token을 무효화한다.
- 회원(계정)당 refresh token은 항상 1개만 유지되므로 동시 활성 세션도 1개로 제한된다. 다른 기기/브라우저에서 새로 로그인하면 기존 refresh token이 새 토큰으로 교체되어 이전 세션은 즉시 무효화된다.

## 관리자 기능

### 1. 대시보드
- 전체 학생 수, 오늘 학습한 학생 수, 진행 중 과제 수, 미제출 과제 수를 지표 카드로 표시한다.
- 최근 7일간 일자별 학습량을 막대그래프로 표시한다.
- 문법 항목별 평균 정답률을 목록으로 표시한다.
- 진행 중/예정 과제 목록을 표로 표시하고, 과제 상세로 이동할 수 있다.
- 마감이 임박했거나 미시작인 학생의 알림 목록을 표시한다.

### 2. 문제 관리
- **Phase 1(MVP) 범위**: 문제 유형은 객관식(`MULTIPLE_CHOICE`)만 지원한다. 빈칸/오류 찾기 유형은 이후 단계 확장 대상이며 Phase 1 범위에 포함되지 않는다.
- 문법 항목·문제 유형·난이도·키워드로 문제 목록을 필터링한다.
- 문제를 클릭하면 상세 정보(문제, 정답, 해설)를 모달로 확인한다.
- 문제 상세에서 수정 또는 사용 중지 처리를 할 수 있다.
- **문제 직접 등록**: 문법 항목, 난이도, 문제 내용, 해설을 입력해 문제를 등록한다. 등록된 문제는 초안 상태로 저장된다.
- **GPT로 문제 생성**: 문법 항목, 난이도, 문제 유형, 생성 개수, 추가 지시사항을 입력하면 문제 초안을 일괄 생성한다.
  - 생성된 문제 목록을 검수 화면에서 확인하고, 개별 문제를 편집하거나 전체를 다시 생성할 수 있다.
  - 검수를 마치면 초안 상태로 일괄 저장한다.

### 3. 과제 관리 (Phase 3 MVP 구현 범위)
- 과제 목록을 상태(예정/진행 중/마감)와 이름으로 검색한다.
- **새 과제 만들기**: 과제명, 대상(반 또는 개별 학생 — 4. 학생 관리의 `group`/학생 ID를 그대로 재사용하며, 별도의 반/그룹 데이터 모델을 새로 만들지 않는다), 시작일(startDate), 마감일(dueDate), 포함할 문제 목록(지정한 순서가 곧 학생에게 노출되는 풀이 순서)을 지정해 과제를 생성한다. 시작일은 마감일보다 늦을 수 없다(`startDate ≤ dueDate`).
- 과제별 제출률(도메인 용어 "진행률" 참고, 관리자 관점 — 최종 제출을 완료한 학생 비율)과 상태를 표로 확인하고 상세 화면으로 이동한다.
- 과제 상세에서 대상·시작일·마감일·문제 구성(순서 포함)을 수정할 수 있다. 마감(`status: 마감`)된 과제는 수정할 수 없다.

### 4. 학생 관리
- 학생 목록을 이름, 그룹, 최근 학습일, 누적 정답률, 미제출 건수와 함께 표시한다.
- 학생 상세로 이동해 개별 학습 현황을 확인한다.
- (향후) 학생 등록 기능은 현재 와이어프레임상 자리만 있고 구현 대상은 아니다.

### 5. 학습 이력 조회
- 학생, 기간(최근 7일/30일 등), 학습 유형(API 값: `ASSIGNMENT`/`PRACTICE`, 화면 표시: 과제/자유 학습)으로 필터링한다.
- 학생별 학습 기록(일자, 유형, 문제 수, 정답률, 학습 시간)을 표로 확인한다.

## 학생 기능

> **Phase 2 구현 완료 범위**: 자유 학습 흐름(문제 조회 → 제출/채점 → 학습 기록 저장·조회)을 백엔드로 구현했습니다.
> **Phase 3(MVP) 구현 범위**: 과제(Assignment) 흐름(내 과제 목록, 문제 풀이용 조회, 답안 임시 저장, 최종 제출/일괄 채점, 진행률, `ASSIGNMENT` 학습 기록 저장)의 계약을 정의하며 이후 구현됩니다. 오답노트(WrongAnswer), 학생 대시보드, 취약 문법 추천 로직은 여전히 Phase 3 범위 밖이며, 아래 섹션 중 이 두 흐름(자유 학습·과제)에 해당하지 않는 내용은 구현 없는 향후 설계 초안입니다.

### 1. 대시보드
- 오늘 푼 문제 수, 오늘 정답률, 오늘 학습 시간, 미완료 과제 수를 지표 카드로 표시한다.
- 해야 할 과제 목록(진행률, 마감일)을 표시하고 바로 이어서 풀거나 시작할 수 있다.
- 취약 문법 TOP 3를 정답률과 함께 표시하고, 취약 문제만 모아 풀 수 있는 진입점을 제공한다.

### 2. 내 과제 (Phase 3 MVP 구현 범위)
- 할당된 과제 목록을 진행률(도메인 용어 "진행률" 참고, 학생 관점 — 임시 저장 여부 기준이며 정답 여부와 무관)과 마감일과 함께 표시한다. 시작일(`startDate`)이 아직 지나지 않아 상태가 `예정`인 과제는 목록에 나타나지 않는다(학생에게는 완전히 숨김 — [내 과제 접근 규칙](#3-b-과제-수행-phase-3-mvp-구현-범위) 참고).
- 미시작 과제는 "시작하기", 진행 중인 과제는 "이어서 풀기" 버튼으로 문제 풀이 화면에 진입한다. 두 버튼 모두 같은 문제 목록 조회로 이어지며, 최초 진입 시 제출 상태(submissionStatus)가 `IN_PROGRESS`로 시작되고 이미 시작한 경우 저장된 임시 답안과 함께 이어서 진행된다.

### 3. 문제 풀이 (자유 학습 / 과제 수행)

문제 풀이 화면은 자유 학습과 과제 수행이 공유하는 UI 컨셉이지만, 백엔드 계약은 서로 다르다. **자유 학습은 Phase 2에서, 과제 수행은 Phase 3(MVP)에서 구현 범위다.**

#### 3-A. 자유 학습 (Phase 2 구현 범위)
- 문법 항목(category)·난이도(level)로 선택적으로 필터링해 **`사용 중` 상태의 객관식 문제를 한 번에 하나씩** 요청한다. 문제 유형은 항상 객관식으로 고정되며(Phase 1(MVP) 범위와 동일), 조건에 맞는 문제가 없으면 안내를 표시한다.
- 객관식 보기 중 하나를 선택해 제출하면 서버가 채점하고, **정답 여부·정답·해설을 즉시 표시**한다(정답/오답에 따라 보기 스타일이 달라진다).
- 같은 문제를 여러 번 다시 풀 수 있으며(재응시), 매 제출은 독립된 학습 기록(StudyRecord)으로 저장된다 — 이전 제출을 덮어쓰지 않는다.
- 자유 학습에는 임시 저장, 진행률, 남은 시간, 문제 번호 이동 개념이 없다(한 번에 한 문제만 다루므로).

#### 3-B. 과제 수행 (Phase 3 MVP 구현 범위)

과제 수행은 CBT(컴퓨터 기반 시험) 방식이다 — 문제를 풀 때마다 채점하는 자유 학습과 달리, 답안은 임시 저장만 되고 채점은 학생이 **최종 제출**을 눌렀을 때 한 번에 이루어진다.

- 시작일(`startDate`)이 지나지 않은(상태: `예정`) 과제는 접근할 수 없다 — 목록에도 나타나지 않고, 직접 접근을 시도해도 존재하지 않는 과제와 동일하게 처리된다(위 [2. 내 과제](#2-내-과제-phase-3-mvp-구현-범위) 참고, API 수준의 상세 접근 규칙은 [docs/api-spec-detail.md](api-spec-detail.md#내-과제-phase-3-mvp-구현-범위) 참고). 마감일(`dueDate`)이 지난(상태: `마감`) 과제는 임시 저장·최종 제출 모두 할 수 없다.
- 과제에 포함된 문제 목록을 순서대로 이동하며 풀이한다(전체 문제 번호로 이동 가능). 문제 순서는 과제 생성/수정 시 지정한 문제 목록의 순서를 따른다.
- 문제마다 답안을 **임시 저장**한다. 임시 저장은 채점하지 않으며, 정답 여부·정답·해설·점수는 최종 제출 전까지 어떤 응답에도 노출되지 않는다. 같은 문제를 다시 임시 저장하면 이전 값을 덮어쓴다(자유 학습의 재응시처럼 기록이 여러 건 쌓이지 않음).
- 임시 저장된 답안은 PostgreSQL에 영속적으로 저장되는 정식 데이터다(캐시가 아님) — 브라우저를 닫거나 서버가 재시작되어도 유지되며, 다시 접속하면 그대로 이어서 풀 수 있다.
- 진행률(임시 저장한 문제 수 ÷ 전체 문제 수)과 마감일까지 남은 기간을 함께 표시한다. 문제별·세션별 제한 시간 개념은 없다.
- **최종 제출**을 하면 그 시점까지 임시 저장된 모든 답안을 한 번에 채점하고, 과제에 포함된 모든 문제마다(임시 저장이 없던 미응답 문제 포함) 학습 기록(StudyRecord, `type: ASSIGNMENT`)을 1건씩 일괄 생성한다. 결과 화면에는 문제별 정답·해설·정오 여부와 총점을 표시한다.
- 최종 제출 이후 제출 상태(submissionStatus)는 `SUBMITTED`로 잠기며, 그 이후로는 같은 과제에 대한 임시 저장도 재제출도 할 수 없다(자유 학습과 달리 과제는 재응시 개념이 없다). 다시 제출을 시도하면 재채점 없이 거부되며, 새로고침이나 나중에 다시 방문해도 같은 채점 결과를 다시 조회할 수 있다(불변 스냅샷 기반 — 아래 4. 내 학습 참고).

### 4. 내 학습 (학습 이력)
- 누적 풀이 수, 누적 정답률, 누적 학습 시간, 해결한 오답 수를 지표 카드로 표시한다. **(Phase 2에서는 자유 학습 기록만 반영했으나, Phase 3 MVP부터 과제 최종 제출로 일괄 생성되는 `ASSIGNMENT` 학습 기록도 함께 반영한다.)**
- 문법 항목별 성취도(정답률)를 목록으로 표시한다.
- 최근 학습 기록을 날짜/유형/문제 수/정답률과 함께 표로 표시한다.
- **(Phase 2 구현) 자유 학습 기록은 제출 건별로 상세 조회할 수 있다** — 언제, 어떤 문제를 풀어 무엇을 제출했고 맞았는지/틀렸는지, 정답과 해설이 무엇이었는지(제출 시점 스냅샷 기준)를 확인한다. 이후 문제가 수정되거나 상태가 바뀌어도 이미 생성된 기록의 스냅샷은 바뀌지 않는다. 자신의 기록만 조회할 수 있다.
- **(Phase 3 MVP 구현) 제출을 마친 과제는 제출 건별 결과를 몇 번이든 다시 조회할 수 있다** — 문제별 정답·해설·정오 여부와 총점을 최종 제출 시 응답과 동일하게 확인한다(재채점 없이 제출 시점의 스냅샷을 그대로 재구성). 미응답 문제도 결과에 포함된다. 아직 제출하지 않은 과제는 결과를 조회할 수 없다(정답/해설/점수 미노출). 여러 과제를 한 화면에서 훑어보는 이력은 위 누적 지표·최근 학습 기록 표(rollup)와 내 과제 진행률로 확인한다.

### 5. 오답노트
- 반복해서 틀린 문제를 문법 항목, 복습 상태(미복습/복습 중/해결)로 필터링한다.
- 문제별 오답 횟수, 최근 오답일, 복습 상태를 표로 표시한다.
- "다시 풀기"로 해당 문제의 풀이 화면에 진입한다.
